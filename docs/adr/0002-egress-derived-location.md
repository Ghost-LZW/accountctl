# 位置每次启动都从代理出口推导，而不是固化进指纹

原来的做法把语言和时区当作指纹的一部分冻结在 `workspace.json`，`geoip = true` 时首次用代理解析一次。两个问题：

1. 分流代理（Clash/mihomo `mode: rule`）下，选题的探测域名可能走直连或另一个节点，解析到的是探测请求的出口，不是目标站点的出口。于是“按 IP 推导”反而制造了矛盾。
2. 代理换节点/换国家后，浏览器仍报旧位置，且改配置要重建已被拒。
3. Camoufox 0.4.11 的 `timezone` 配置项不生效，原实现靠 `TZ` 环境变量兜底；`geoip` 还默认禁用 WebRTC，正常浏览器却没有 WebRTC 本身就是特征。

新做法把“随机身份”（Canvas、WebGL、字体种子、UA、屏幕）与“位置身份”分开。位置在**每次启动前**重新获取：用同一个代理、强制忽略 `NO_PROXY`，向两个独立端点查询；两端 IP 必须一致，否则按分流不一致拒绝启动。位置由本地 MaxMind 数据库解析，语言取该国常用语言（同国内保持已选项）。`TZ`、`CAMOU_CONFIG`、`LANG/LC_ALL`、`intl.accept_languages`、geolocation、WebRTC 对外 IP 全部由它派生。启动后在第一张真实页面回读 `Intl` 时区和 `navigator.language`，不符则关闭会话。

显式写死 `locale`/`timezone` 仍支持，但变成“受校验的断言”：时区与出口时区相差超过 3 小时、语言不是出口国前两位语言，就拒绝启动（3 小时是为了容忍同国跨时区，美国东西岸即 3 小时）。这样既保留可钉定的能力，又不允许静默矛盾。

策略 `egress`：`auto`（默认，跟随）、`strict`（换国家拒绝）、`warn`（只记录）、`off`（旧行为）。`strict` 用于不希望登录身份今天在美国明天在德国的账号。

不采用浏览器内探测（打开目标页后再取 IP）作为唯一来源：指纹必须在启动浏览器前算出来；两个端点 + 本地库已经能区分“代理没通”和“代理分流不一致”，而前者本来就是硬错误。

WebRTC 默认由“关闭”改为“伪装成出口 IP”：关闭会让 `RTCPeerConnection` 缺失，伪装更接近正常浏览器；同时关掉 host 候选混淆之外的 IPv6 候选。旧 profile 默认 `keep`。

**已知构建问题**：配置了 geolocation 后，在这个构建上 `navigator.geolocation.getCurrentPosition()` 会阻塞页面事件循环，JS 侧 `setTimeout` 也不触发。因此启动回读只校验时区和语言，坐标的正确性由单元测试覆盖，不在启动路径上等它。
